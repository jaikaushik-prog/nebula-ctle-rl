# Entry 110: clean-input buffers plus memory

Frozen 2026-09-06 before measurement. Owner approved the proposed single
isolated buffer-plus-memory check after Entry 109 and read-only pulse analysis.

## Fixed circuit and one-call budget

Exactly one TT / 1.8 V / 27 C SPICE transient, no retries or PVT follow-up.
Use the existing Entry 107 width-4 circuit's eight buffer MOS and eight memory
MOS verbatim from `dfe_hardware.dut_lines(4, buffered=True)`. Every transistor
remains W=4 um, L=.15 um, nf=2. Remove only the comparator from this diagnostic
bench; no changes to the actual connected prototype or production product.

Drive raw buffer inputs x/y with Entry 109's exact clean external waveforms:
same LinkConfig seed=1, 36 bits, four warmup, 200 ps UI, 2 ps edges,
active-low full-swing pulses from evaluation edge to +100 ps. The buffer
outputs bx/by are generated by real MOS, never forced by test sources.
No output initial condition, artificial load, extra clock, phase adjustment,
width sweep or behavioral decision inside the DUT.

Reuse Entry 109's strict finite/time/source validation and unchanged q/qb
held-bit check from +110 through +190 ps at VDD/2 for all 32 scored bits.
Validate and retain all four intermediate buffer nodes on the exact same
solver time axis. Report buffer low arrival/release as diagnostics, not new
acceptance thresholds. A delayed release may extend active driving into the
held window; report it rather than equating the entire window to retention.
No raw comparator pass can be claimed since that comparator is absent.

## Interpretation and stopping rule

- Pass: the unchanged buffers and memory work under early, stiff, full-swing
  drive at nominal. Investigate their interaction with the real comparator;
  this is not proof that the real comparator can provide such waveforms.
- Fail: even this clean-input buffer/memory path misses the existing window.
  Inspect its delay/drive before proposing a revised interface.
- In either case stop after one call. Do not promote to full decision/hold,
  hardware DFE, PVT, feedback or receiver compliance. Get owner approval for
  any new architecture, dimensions or timing. Keep Rs/Cs, CTLE/RL, dashboard,
  behavioral DFE, cached demo and report unchanged.

Keep exact deck, raw waveforms, log, config, source/plan snapshots and hashes.
Use the existing strict fresh-process launcher and shared `dfe_slicer` lock.
Report full DUT supply power separately from ideal external-source energy;
MOS W*L geometry is not complete layout area. Tests precede implementation;
full before/after regression and raw-result reproduction are required.
